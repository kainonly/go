# AGENTS.md

## Project

Go utility library for web services (`github.com/kainonly/go`) with
Hertz-friendly integrations. Each directory is an independent package; users
import only what they need. Requires Go 1.25+.

## Commands

```bash
go build ./...    # compile all packages
go vet ./...       # static analysis
go test ./...      # run tests (Redis-backed tests are skipped without DATABASE_REDIS)
```

The `captcha` and `locker` packages depend on Redis and silently skip their
tests when the `DATABASE_REDIS` environment variable is unset. To run the full
suite:

```bash
docker run -d --name redis -p 6379:6379 redis:7-alpine
DATABASE_REDIS=redis://127.0.0.1:6379 go test -race ./...
```

## Documentation Conventions

- All comments, documentation, commit messages, and user-facing strings are in
  English.
- Detailed usage lives in package doc comments (godoc format), not in
  separate docs directories. When adding a feature, document it there using
  the `# Heading` godoc syntax with runnable example code. Hertz backend and
  Angular frontend usage examples are included where relevant (see `captcha`,
  `csrf`, `passport`).
- There is no CHANGELOG file; release notes are auto-generated by the release
  workflow.

## Code Conventions

- Options pattern: constructors accept variadic `Option` functions
  (e.g. `csrf.SetKey`, `captcha.SetPrefix`).
- Errors are package-prefixed sentinel values (e.g. `locker.ErrLocked`,
  `passport.ErrInvalidIssuer`).
- Redis-backed packages namespace their keys with a configurable prefix.
- Validation rules in `vd` are pure functions returning a `Rule` struct, with
  regexes compiled lazily via `sync.OnceValue`.

## CI

GitHub Actions (`.github/workflows/`):

- `testing.yml` — push to main and PRs; starts Redis via docker compose, runs
  `go test -race` with coverage, reports to Coveralls.
- `release.yml` — on `v*` tags; runs tests, creates a GitHub Release with
  auto-generated notes, then pings the Go module proxy to index the version.
